Create a separate Staff Portal for Housekeeping and Support Staff. This portal must be completely different from the regular employee portal. Keep the UI extremely simple, mobile-first, with large buttons, minimal text and easy navigation.

Do not include Dashboard Analytics, Tasks, Notes, Issue Reporting, Payslips, Announcements, Attendance History, Calendar, Settings or Profile Editing.

Features:

1. HOME

Display only one attendance button.

If not checked in:
🟢 Check In

After Check In:
Show "Checked In Successfully" with check-in time and replace the button with:
🔴 Check Out

After Check Out:
Show "Shift Completed Successfully" with check-out time.

Do not ask for notes during Check In or Check Out.

2. APPLY LEAVE

Fields:
• Leave Date
• Apply Button

No reason or description field.

After submission:
Show "Leave Request Submitted Successfully."

The request should automatically appear in the HR portal for approval.

3. APPLY PERMISSION

Fields:
• Permission Date
• Permission Duration

Use radio buttons instead of a dropdown.

Options:
○ 30 Minutes
○ 1 Hour
○ 1 Hour 30 Minutes
○ 2 Hours

Allow only one option to be selected.

Rules:
• Maximum 2 permission requests per calendar month.
• Maximum duration per request is 2 hours.
• If the employee has already used 2 permissions in the current month, disable the Apply button and display "You have already used your maximum 2 permissions for this month."

After submission:
Show "Permission Request Submitted Successfully."

The request should automatically appear in the HR portal for HR approval.

4. PROFILE

Display only:
• Employee Name
• Employee ID
• Department
• Designation
• Manager
• Phone Number
• Joining Date

No editing options.

5. LOGIN

Employees log in once using their existing credentials. Keep the device logged in permanently unless HR resets the device or the employee logs out manually.

BOTTOM NAVIGATION

• Home
• Leave
• Permission
• Profile

Maintain role-based access so only Housekeeping and Support Staff can access this simplified portal. All other employees should continue using the existing employee portal.

Do not modify the existing HRMS workflow or functionality. Reuse the existing authentication, database and APIs. Follow the current project architecture, use reusable components, strong TypeScript typing, responsive design and clean production-ready code.
